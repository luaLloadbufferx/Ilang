# Ilang

Ilang is a small, statically typed programming language with its own compiler and virtual machine.

| Component | Language | Role |
| --- | --- | --- |
| **Ilangc** | C++17 | Compiler: turns an Ilang source file (`.i`) into bytecode (`.ic`) |
| **IlangVM** | C11 | Virtual machine: runs the bytecode |
| **Ilangdis** | C11 | Disassembler: turns bytecode back into a readable listing |

```
program.i -> Ilangc -> program.ic -> IlangVM -> output
```

## Features

- **Static types:** `int`, `uint`, `float`, `bool`, `byte`, `string`, arrays and structs
- **Automatic memory management with no garbage collector:** the compiler releases strings, arrays and structs when they go out of scope
- **Tail calls run in constant stack space:** `return f(...)` (and a trailing call in a `-> void` function) compiles to a jump, so tail recursion can go millions of calls deep
- **Bounds-checked array and string access,** with `unsafe` blocks for hot loops
- **Helpful compiler errors** that show the source line and suggest fixes
- **Built-in console and file I/O**
- **C interop:** call C functions from Ilang and Ilang functions from C

## Example

```
fn fib(n: int) -> int {
    if (n < 2) { return n; }
    return fib(n - 1) + fib(n - 2);
}

fn main() {
    print("fib(10) = " + str(fib(10)) + "\n");
}
```

More example programs are in `IlangVM/pgo_src/`.

## Building

You need a C++17 compiler for the compiler and a C11 compiler for the VM.

**Compiler**

```sh
g++ -std=c++17 -O2 Ilangc/main.cpp -o Ilangc/ilangc
```

**Virtual machine**

```sh
gcc -O2 IlangVM/main.c IlangVM/VM/*.c -o IlangVM/ilangvm -ldl
```

> `-ldl` is needed on Linux; leave it out on macOS and Windows.

**Disassembler**

```sh
gcc -O2 Ilangdis/*.c -o Ilangdis/ilangdis
```

`build.sh` / `build.bat` build all three tools in one go. `build.sh` writes `Ilangc/ilangc`, `IlangVM/ilangvm` and `Ilangdis/ilangdis`; `build.bat` writes `ilangc.exe`, `ilangvm.exe` and `ilangdis.exe` into the project folder.

## Disassembler

```sh
ilangdis program.ic              # listing with jump and call arrows
ilangdis -b program.ic           # ... and the raw bytes of every instruction
ilangdis -f program.ic           # the functions it found
```

## Tail calls

A call whose result is returned unchanged does not need the caller's frame, so the compiler turns it into a jump:

```
fn sum(n: int, acc: int) -> int {
    if (n == 0) { return acc; }
    return sum(n - 1, acc + n);      // a jump: a million levels use no more stack than one
}
```

This covers `return f(...);`, mutual recursion (`is_even` / `is_odd` written with `if` and `return`), and, in a function declared `-> void`, a call that is the last thing the function does. (A function without `->` returns `int`, so a trailing call there is not a tail call.)

The call stays an ordinary call, and a very deep recursion still overflows the VM's stacks, when

- the call is not the whole returned expression (`return 1 + f(x)`, `return c ? f(x) : g(x)`);
- the callee is an `extern fn`, or returns a different type;
- the callee is another function that takes more arguments than fit in registers;
- an argument is a string, array or struct that would not survive the jump: a temporary (`f("a" + s)`) or one that belongs to a local variable. Passing on a parameter or a global is fine.

Recursion that is not a tail call (`n * fact(n - 1)`, `fib(n - 1) + fib(n - 2)`) still uses a frame per level and is limited by the VM's stacks: `MAX_STACK_SIZE` (320 values) and `MAX_CALL_DEPTH` (1280 entries) in `IlangVM/VM/IlangConf.h`. With the defaults that is about 321 levels for a factorial; write it with an accumulator (`fact(n - 1, acc * n)`) to go as deep as you like, or build the VM with larger limits.
